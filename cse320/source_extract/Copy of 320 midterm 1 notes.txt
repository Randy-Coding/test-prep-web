P93: Memory Locality Principles
P94: Two core principles for hardware optimization:
P95: Temporal locality: recently used data likely to be used again
P96: Spatial locality: accessing array[i] means likely to access array[i+1], array[i+2] soon
P97: Code structure impacts hardware performance
P98: Good: accessing array elements sequentially (spatial locality)
P99: Bad: random memory access patterns
P100: Loop optimization considerations:
P101: Inlining functions improves spatial locality (avoids jumps)
P102: Loops create temporal locality (same instructions repeated)
P103: Excessive loop unrolling can hurt performance (O3 sometimes worse than O2)
P104: Array Access Patterns & Performance
P105: Matrix operations require careful loop ordering
P106: Good: for(k) for(i) for(j) - stride-1 access pattern
P107: Bad: for(i) for(j) for(k) - creates large memory jumps
P108: Stride analysis for 3D arrays:
P109: J increment: stride = 1 (best)
P110: I increment: stride = N
P111: K increment: stride = N×N (worst)
P112: Real-world complexity: matrix multiply operations often can’t be easily reordered due to algorithmic constraints

P186: Cache Architecture Fundamentals
P187: Cache sits between CPU registers and RAM
P188: Three types of cache misses:
P189: Cold/compulsory: First access after startup
P190: Capacity: Data set larger than cache size
P191: Conflict: Multiple addresses map to same cache location
P192: Cache design spectrum:
P193: Direct mapped: Each RAM address has one designated cache slot (simple hardware, more conflicts)
P194: Fully associative: Any RAM block can go anywhere in cache (complex hardware, no conflicts)
P195: Set associative: Middle ground with sets and lines

P197: Cache block structure: Valid bit + Tag + Data bytes
P198: Address breakdown: Tag bits + Set index + Block offset
P199: Replacement policies determine which block to evict
P200: Dirty blocks must be written back to memory before eviction
P201: Spatial/temporal locality critical for performance
P202: 99% hit rate makes 1% miss overhead acceptable
P203: sys 7
P204: Cache Memory Fundamentals
P205: Cache definition: smaller, faster data store as shortcut to larger storage
P206: Memory hierarchy: ranges from slow/large (hard drives) to fast/small (registers, cache)
P207: Data shuffles between hierarchy levels from larger/slower to smaller/faster devices
P208: Cache design trade-off: direct mapped (fast hardware, more misses) vs fully associative (slower hardware, fewer misses)
P209: Set associative cache: tunable parameter balancing both approaches
P210: Most common solution across industry
P211: Cache Architecture & Address Mapping
P212: Cache structure: grid of blocks storing multiple bytes each
P213: Block size rationale: accessing consecutive memory costs same as single byte
P214: Address breakdown into three parts:
P215: Tag bits: identify which memory block is stored
P216: Set bits: determine which cache set (row) to use
P217: Block offset bits: specify byte within block
P218: Calculation method: log base 2 of memory size gives total address bits
P219: Example walkthrough with 16-byte memory, 2-byte blocks, 4 sets
P220: 4 address bits total (log₂ 16)
P221: 1 block offset bit (log₂ 2)
P222: 2 set bits (log₂ 4)
P223: 1 tag bit (remaining)
P224: Cache Performance & Replacement
P225: Set associative cache allows multiple lines per set
P226: Cache replacement algorithms:
P227: Optimal (theoretical): replace least-used-in-future block
P228: LRU (Least Recently Used): most common, uses past to predict future
P229: FIFO (First In, First Out): simpler but worse performance
P230: Real-world cache hierarchy example:
P231: L1: 32KB, 8-way, 4 cycles, split I-cache/D-cache
P232: L2: 256KB, 8-way, 10 cycles per core
P233: L3: 8MB, 16-way, 50-75 cycles shared
P234: All use 64-byte blocks (6 bits block offset)
P235: Write Policies & Performance Impact
P236: Write-through: immediate write to both cache and memory
P237: Good for data consistency, bad for memory bus usage
P238: Write-back: delayed write using dirty bit until eviction
P239: Good for memory bus, requires careful consistency management
P240: Write allocation policies:
P241: Write allocate: load from RAM to cache on write miss (most common)
P242: No-write allocate: write directly to RAM (rare, used for I/O devices)
P243: Miss rate more important than hit rate for performance analysis
P244: 97% hit rate = 4 cycle average (3% × 100 cycle penalty)
P245: 99% hit rate = 2 cycle average (1% × 100 cycle penalty)
